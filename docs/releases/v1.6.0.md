## 四个机制

### 1. Fold operator

**内容：** 把 `wiki/log.md` 条目做 extractive rollup，写入 `wiki/folds/`。

**调用：**

```text
fold the log, dry-run k=3
fold the log, commit k=3
```

**跳过场景：** log 没有形成连贯批次，或你想要的是删除式压缩。fold 是总结，不是垃圾回收。

**状态：** `1.5.0` 发布。第一次真实运行生成：

```text
wiki/folds/fold-k3-from-2026-04-23-to-2026-04-24-n8.md
```

观察结果：115 行、8 个 child、flat extractive fold。

### 2. 确定性页面地址

**内容：** 给新的非 meta wiki 页面添加稳定 frontmatter：

```yaml
address: c-NNNNNN
```

**调用：**

```bash
./scripts/allocate-address.sh
```

或让 `wiki-ingest` 在 DragonScale setup 后自动分配。

**跳过场景：** 不需要稳定页面 ID，或同一时间可能有多个 writer 分配地址。

**状态：** `1.5.0` 发布。格式示例：`c-000042`。它是 creation-order counter，不是内容哈希。

验证运行中，counter 从 2 前进到 3，返回 `c-000002`。未分配 reservation gap 被 spec 接受。

### 3. Semantic tiling lint

**内容：** 基于 embedding 的重复页面检测。

**调用：**

```bash
python3 ./scripts/tiling-check.py --peek
python3 ./scripts/tiling-check.py --report wiki/meta/tiling-report-YYYY-MM-DD.md
```

**跳过场景：** `ollama` 或 `nomic-embed-text` 不可用，或未校准 review bands 会制造更多噪声。

**状态：** `1.5.0` 发布。默认模型是本地 ollama 中的 `nomic-embed-text`。

默认分档：

- `>= 0.90`：error；
- `0.80` 到 `0.90`：review；
- `< 0.80`：pass。

这些是种子值，不是针对当前 vault 的校准结果。

第一次完整报告：

```text
wiki/meta/tiling-report-2026-04-24.md
```

### 4. Boundary-first autoresearch

**内容：** 对 wiki 页面做 frontier scoring，用作无 topic `/autoresearch` 的候选主题。

**调用：**

```text
/autoresearch
```

或：

```bash
python3 ./scripts/boundary-score.py --json --top 5
```

**跳过场景：** 只想显式控制 topic，或希望 DragonScale 只覆盖纯 memory operations。

**状态：** `1.6.0` 发布。

公式：

```text
boundary_score(p) = (out_degree(p) - in_degree(p)) * exp(-days_since_updated / 30)
```

它寻找向外连接多、入链少、最近仍有活性的页面。它不是纯记忆，而是 agenda control；最终仍由用户选择主题。

第一次运行产物：

```text
wiki/meta/boundary-frontier-2026-04-24.md
```

观察：22 个可评分页面，7 个正分页面，最高分 `4.693`，`DragonScale Memory` 得分 `4.000`。

## 龙曲线类比

Heighway dragon 由 paperfolding recursion 构造。每一步把一个 turn sequence 折进更大的自相似序列。对应序列是 OEIS A014577。参考 [Dragon curve](https://en.wikipedia.org/wiki/Dragon_curve)。

其边界 fractal dimension 约为 `1.5236`。这里它只是方向感，不是证明：边界既不是简单线段，也不是填满平面，而是有结构的 frontier。

这个类比适合作为记忆层的直觉：

- 递归结构对应 hierarchical rollup；
- 自相似边界对应 frontier-first agenda；
- 但 DragonScale 并没有从曲线几何推导出最优记忆行为。

## v1.6.0 不包含什么

- 没有 fold-of-folds。
- 没有多层 hierarchical stacking。
- 不自动删除或压缩 child pages。
- 没有校准过的 M3 阈值。
- 没有针对当前 vault 的文献背书 M3 bands。
- 不根据 tiling 自动合并页面。
- 不声称 M4 是纯 memory。
- 不在 M4 中隐藏选择 topic。
- 没有 hosted 或 managed mode。
- 没有多 vault fold rollup。
- 没有多写者地址分配保证。
- boundary scoring 没有 alias-aware 的完整 Obsidian wikilink resolver。
- 没有持久 boundary-score cache。
- 不自动触发 autoresearch。

## 从 v1.4.x 升级

对基础用户是非破坏性升级：

1. Pull `main`。
2. 如果 agent setup 需要，重新安装插件。
3. 如果不想用 DragonScale，继续使用 v1.4.x 的普通 wiki workflow。
4. 准备好后再 opt in：

```bash
bash bin/setup-dragonscale.sh
```

如果不 opt in，v1.4.x workflow 不变。DragonScale 是 feature-detected；`wiki-ingest`、`wiki-lint`、`/autoresearch` 在 setup 状态或 helper 依赖缺失时回退。
