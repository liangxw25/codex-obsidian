## Fix 1（BLOCKER）— `contextual-prefix.py` 数据外发 consent 缺口

**严重级别：** BLOCKER，公开 push 前必须修  
**文件：** `scripts/contextual-prefix.py`  
**先例：** `scripts/tiling-check.py` 中 `--allow-remote-ollama` flag + localhost guard

### 问题

`pick_prefix_tier()` 会在 `ANTHROPIC_API_KEY` 存在时自动选择 `anthropic-api`，或在 `claude` 命令存在时选择 `claude-cli`：

```python
def pick_prefix_tier(force_synthetic):
    if force_synthetic:
        return "synthetic"
    if os.environ.get("ANTHROPIC_API_KEY"):
        return "anthropic-api"
    if shutil.which("claude"):
        return "claude-cli"
    return "synthetic"
```

这会把 wiki page bodies 发送到机器外部，没有 prompt、没有 flag、没有 warning。对于 Claude Code 用户，环境中常常已经有 `ANTHROPIC_API_KEY`，因此风险很现实。

### 修改

1. `scripts/contextual-prefix.py`：新增 `--allow-egress`，默认 `False`。未提供该 flag 时，无论环境变量和 `claude` 是否存在，都使用 `synthetic`。

```python
parser.add_argument("--allow-egress", action="store_true",
    help="Allow tier-1 (Anthropic API) or tier-2 (claude CLI subprocess) "
         "prefix generation. Without this flag, page bodies stay on-machine.")

def pick_prefix_tier(force_synthetic, allow_egress=False):
    if force_synthetic or not allow_egress:
        return "synthetic"
    if os.environ.get("ANTHROPIC_API_KEY"):
        return "anthropic-api"
    if shutil.which("claude"):
        return "claude-cli"
    return "synthetic"
```

2. `bin/setup-retrieve.sh`：在非 `--no-llm` 且非 `--check` 时，对非 synthetic tier 弹出明确 prompt，默认 no。

3. `skills/wiki-retrieve/SKILL.md`：顶部加入 **Data privacy (v1.7.1+)**，说明 tier 1 / tier 2 会外发页面正文，默认由 `--allow-egress` 和 setup prompt 守卫；完全本地路径用 `bash bin/setup-retrieve.sh --no-llm`。

### 验证

```bash
make test

python3 scripts/contextual-prefix.py wiki/concepts/Hot\ Cache.md --peek
# 预期：tier=synthetic

ANTHROPIC_API_KEY=test python3 scripts/contextual-prefix.py wiki/concepts/Hot\ Cache.md --peek --allow-egress
# 预期：tier=anthropic-api

echo "" | bash bin/setup-retrieve.sh
# 预期：出现 prompt，空输入默认 abort
```

### Commit message 摘要

```text
fix(v1.7.1): contextual-prefix egress requires explicit consent
```

该 commit 同时关闭 B1 和 H6。

## Fix 2（HIGH H1）— `setup-retrieve.sh` Stage 1 中途失败无 rollback

**文件：** `bin/setup-retrieve.sh`

### 问题

Stage 1 运行 `contextual-prefix.py --all`，如果中途失败，partial `.vault-meta/chunks/` 会留在磁盘，Stage 2 可能继续用陈旧索引，用户没有恢复说明。

### 修改

捕获 Stage 1 非零退出，打印恢复选项，并退出：

```bash
if ! python3 "$VAULT/scripts/contextual-prefix.py" "${ARGS[@]}"; then
  STAGE1_RC=$?
  warn "Stage 1 failed (rc=$STAGE1_RC). Partial chunks are at:"
  warn "  $META/chunks/"
  warn "Recovery options:"
  warn "  1. Re-run setup-retrieve.sh — incremental skip will resume from body_hash"
  warn "  2. Wipe and start over: rm -rf $META/chunks/ && bash bin/setup-retrieve.sh"
  warn "  3. Provision the failed page only: python3 scripts/contextual-prefix.py wiki/<failing-page>.md --rebuild"
  exit 5
fi
```

### Commit message

```text
fix(v1.7.1): setup-retrieve rollback path on Stage 1 failure
```

## Fix 4（HIGH H3）— PostToolUse hook 的 `|| true` 吞掉 lock-check 错误

**文件：** `hooks/hooks.json`

### 问题

PostToolUse command 是一条长 pipeline，以 `|| true` 结尾。若 `bash scripts/wiki-lock.sh list` 失败，错误被吞掉，`git add/commit` 仍可能发生。安全属性从“有锁时延迟提交”退化成“未知状态也提交”。

### 修改

重构 hook，单独捕获 lock-list exit code。若 lock check 失败，退出 0 并推迟 auto-commit，而不是继续。

关键原则：

- 先 `[ -d .git ] || exit 0`；
- 若 `scripts/wiki-lock.sh` 可执行，计算 `LOCK_COUNT`；
- `LOCK_RC != 0` 时退出；
- `LOCK_COUNT != 0` 时退出；
- 最后的 `|| true` 只包住 git 操作。

### Commit message

```text
fix(v1.7.1): PostToolUse hook tests lock-check exit code explicitly
```

## Fix 5（HIGH H5）— `detect-transport.sh` JSON escaping

**文件：** `scripts/detect-transport.sh`

### 问题

`obsidian-cli --version` 输出通过 shell variable expansion 直接进入 JSON，只删除了双引号，未处理换行、反斜杠和控制字符。

### 修改

新增 helper：

```bash
json_escape() {
  python3 -c 'import json,sys; print(json.dumps(sys.stdin.read().strip()), end="")'
}
```

然后将 version string 作为已经 quote 过的 JSON string 写入：

```bash
CLI_VERSION="$(obsidian-cli --version 2>/dev/null | head -1 | json_escape || echo '"unknown"')"
```

heredoc 中去掉额外双引号：

```json
"version_string": ${CLI_VERSION}
```

### Commit message

```text
fix(v1.7.1): detect-transport.sh escapes version_string as JSON
```
