## 0. 为什么需要这个计划

三轮 verifier + chair 审查收敛到 `97/100`：

| 轮次 | 结果 |
|---|---|
| Round 1 | 初始 v1.7.1 fixes；chair 打 96；verifier 后续又发现 5 个 polish items |
| Round 2 | polish commit；verifier 说 SHIP 0/0/0/0；chair 又发现 2 个，再更强 probe 发现 3 个 |
| Round 3 | chair-probe fixes；verifier 说 SHIP 1 LOW；chair inline 修掉 |

剩余扣分是结构性的：

1. `main..HEAD` 约 `+5819 / -30 LOC`，与 “delete more than you add” 相反；
2. 需要三轮才收敛，说明切片纪律不足；
3. v1.7.0 audit 中还有 14 个 MEDIUM 和 10 个 LOW 需要关闭或正式推迟。

真正的 `100/100` 要求这些都被关闭，或用明确 milestone 和理由推迟。

## 1. 验收标准

计划执行前先定义成功标准：

1. 最终 verifier 对整个 `main..HEAD` diff 返回 **0 BLOCKER / 0 HIGH / 0 MEDIUM / 0 LOW**；
2. 最终 chair adversarial probe（至少 10 个具体测试）无 functional findings；
3. LOC delta 有非平凡删除：net additions ≤ +5000 **或** deletions ≥ 200；
4. 每个 M1-M14 + L1-L10 均 CLOSED（带 commit SHA）或 DEFERRED（带 milestone 和理由）；
5. `make test` 全程 green；
6. 未经用户明确授权，分支保持本地；
7. `agents/verifier.md` 增加 git-hygiene cut 和这三轮 retrospective 中学到的检查项。

如果无法满足，按实际得分发布，并明确记录 gap。

## 4. Phase 2 — 处理 `+5819 / -30 LOC`

**目标：** prune 被 v1.7 替代但未删除的 v1.6 cruft。

候选扫描：

```bash
grep -rn "v1\.6\|legacy\|deprecated\|TODO\|FIXME" skills/ scripts/ bin/
grep -rn "^## .*1\.6\|^### .*1\.6" skills/
grep -rn "allowed-tools: .*Edit\|allowed-tools: .*Write" skills/
```

每个候选分为：

- **PRUNE**：v1.7 后已死的代码或文档；
- **KEEP**：仍然有用；在 scratch file 写一行理由。

每组 prune 后运行 `make test`。结束 gate：

- net additions ≤ +5000，或
- deletions ≥ 200。

失败模式：如果 v1.7 确实主要是新增 substrate，不存在可诚实删除的旧面，就在审计里明确说明，不能为了指标伪造删除。

## 8. Phase 6 — 最终验证和 ship gate

二进制 gate：通过，或接受实际分数；不要无限递归。

8. 查看 `git diff --shortstat main..HEAD`；
9. changed files 中 `TODO|FIXME|XXX` 无净新增；
10. 打开每个改动文档，确认 commit-SHA 引用能解析。
